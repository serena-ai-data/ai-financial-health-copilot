01 · Problem

Users have financial apps. They still lack a whole picture.

Bank accounts, credit cards, insurance and investments often live across different providers. Product-level information exists, but the user may still not know what matters most right now.

1

Fragmented information

Financial facts sit across multiple apps, statements and policies.

2

Complex interpretation

Terms, ratios and policy language are difficult to translate into an overall position.

3

No action priority

Users receive information but still struggle to decide what deserves attention first.

02 · Product

From data to insight to action.

The MVP is deliberately narrow: understand overall financial health before attempting transactions, trading or autonomous financial decisions.

Consent→Add data→Review & verify→Deterministic analysis→Dashboard→Explainability→Action plan

Transparent scoring

Cash flow, emergency reserve, short-term debt and protection status use visible rules rather than an opaque LLM score.

Explainability on demand

Every material result can expose the input, formula, rule and known uncertainty behind it.

Prioritised next action

The product ranks what to review first instead of returning a generic list of financial tips.

04 · Prioritised backlog

Ship the trust-critical path before the intelligence layer.

P0 establishes safe, reviewable financial state. P1 turns that state into understandable value. P2 adds richer AI and connected-data capabilities after the core hypothesis is proven.

P0
Consent & AI-boundary disclosure
Required before collecting sensitive financial data.
P0
Structured input + review & correction
Prevents bad or uncertain data from silently influencing results.
P0
Deterministic financial-health analysis
Provides reproducible calculations and a stable source of truth.
P1
Explainability + prioritised action
Converts financial state into understandable, useful next steps.
P2
AI Copilot + connected financial data
Adds richer interpretation and continuity after the core workflow is validated.

Example user story

As a user, I want to review the financial information that will influence my result so that incorrect or uncertain data does not silently affect the recommendation.

Acceptance criteria

Material inputs are visible and editable; required fields must be valid; uncertain data is not promoted to verified fact; corrected values must feed the next calculation.

05 · Roadmap & trade-offs

Sequence capability only as controls mature.

The roadmap deliberately moves from understanding to connected context, then to personalised action, and only later to governed execution.

MVP

Financial understanding

Manual input, review, deterministic analysis, explainability and next-best action.

V2

Connected context

Bank / wallet / insurance connectors, source traceability and stronger exception handling.

V3

Personalised action

Goal planning, contextual nudges, deeper analysis and experimentation.

V4

Governed execution

Human-confirmed actions, suitability controls, approval logic and stronger audit trails.

Real integrations vs manual input

Start manually to validate the user problem before investing in expensive integrations.

LLM score vs deterministic score

Choose deterministic scoring because reproducibility and auditability matter more than novelty.

Autonomous action vs confirmation

Keep the user in control until compliance, operational and technical safeguards are mature.

Perfect data vs bounded progress

Allow useful decisions with visible limitations instead of pretending uncertainty does not exist.

07 · Trust & AI

AI explains. Rules calculate. Users stay in control.

The differentiator is not simply adding a chatbot. It is designing where AI is useful, where it must stop, and how a user can inspect or challenge the result.

AI can interpret and explain.

Summarise verified information, explain outcomes, surface uncertainty and answer grounded questions.

✓ Explain verified results
✓ Summarise complex financial documents
✓ Surface uncertainty and missing context
Fact → Rule → Application → Conclusion → Uncertainty

This explainability pattern is intentionally influenced by legal reasoning and auditability. A recommendation should be traceable to confirmed facts and visible rules rather than presented as an authoritative black-box answer.

Consent before sensitive-data collection
Review and correction before analysis
Source traceability
Audit-trail thinking
Human verification for uncertain conclusions
08 · Localisation

Same platform, different user problem.

The core product can be reusable, but localisation should start with the local financial problem, regulation, trust model and infrastructure — not simple translation.

China hypothesis

Focus on financial fragmentation, cross-provider views, cross-insurer organisation, liquidity, accessibility, scam warnings, sensitive-data consent and explainable guidance rather than basic mobile-payment access.

Southeast Asia hypothesis

Depending on market: remittance, accessible protection, wallet-first journeys, financial inclusion, Takaful/Shariah considerations, lightweight mobile experiences and multi-currency needs.
