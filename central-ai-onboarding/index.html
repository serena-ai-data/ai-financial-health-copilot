Central AI Onboarding Redesign

A hypothesis-driven redesign exploring how a multi-module AI business platform could move a new SMB user from signup to a first successful AI action with less setup friction. / 一个围绕“新用户如何更快第一次真正用上 AI”的上手流程优化案例。

1. Product hypothesis / 产品假设

A broad AI platform can be powerful but cognitively expensive for a first-time user. My hypothesis: onboarding should begin with the user's desired outcome, then progressively reveal only the integration and permissions required for that outcome.

Friction hypothesis 1

Too many capabilities before the user knows where to start.

Friction hypothesis 2

Integration setup feels like work before any value is demonstrated.

Friction hypothesis 3

“Setup complete” is not the same as “AI successfully helped me.”

Important

These are portfolio hypotheses to be validated with real funnel data and user research. No production conversion or drop-off numbers are claimed.

2. Proposed journey / 建议流程

Replace module-first onboarding with outcome-first onboarding.

Choose desired outcome→Connect only required tool→Set AI permissions→Generate first useful output→Approve first AI action→Recommend next module

Outcome first

“Manage my inbox”, “Answer customer calls”, “Schedule meetings”, or “Follow up leads”.

Progressive disclosure

Show only the integration required for the selected job, then reveal more after activation.

First value

The moment AI identifies or completes real work, not when the settings wizard ends.
